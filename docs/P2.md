# P2 investor tools

P2 extends stored run evidence and the existing profile flow. Read operations never call an
external provider. Deterministic tools work in replay mode without additional recordings.

## F-13 risk screening

The property page screens frozen locality news for flood, title/construction disputes and
oversupply mentions. A cited mention scores 50/100 as an investigation flag, not severity or
probability. Coverage counts categories with evidence. Missing reports remain unknown; they
never become a low-risk rating. These indicators do not change ranking. Check the source and
commission property-specific drainage, title and inventory checks before relying on a lead.

Code: `schemas/risk.py`, `services/risk.py`, `services/properties.py`, `RiskCard.tsx`.
Run `cd backend && uv run pytest tests/unit/test_risk.py tests/integration/test_property_detail.py`.

## F-14 trend projections

Run development responses now project public search interest 4 and 12 weeks ahead with a
26-week linear fit. At least 26 consecutive, recent, sourced, non-sparse weekly points are
required. The final 4 observations are held out for a mean absolute error check. Error bands
are descriptive, not statistical confidence guarantees. Outputs stay within the source index
range 0-100. Old runs keep their original as-of date. No price projection can be inferred from
a single annual price-growth observation; search interest is explicitly separate from ROI.
App history is not extrapolated, and ranking/metrics remain unchanged. The development panel
shows results, error, method and unavailable-data explanations.

Debug with `uv run pytest tests/unit/test_forecast.py tests/integration/test_development_api.py`.

## F-15 PDF export

Use **Download PDF report** on a property page, or
`GET /api/properties/{id}/report.pdf?run_id={run}`. ReportLab lays out paginated property facts,
metrics with confidence/method, relevance, quality/risk checks, locality evidence and full
source URLs. Reads use the same stored snapshot as the page; exports cost no searches and
are not cached by the browser. Unknowns and gross/historical assumptions stay visible.
`uv run pytest tests/integration/test_reports_api.py` validates real replay exports using pypdf.

## F-16 portfolio tracker

The Portfolio screen supports add, edit and remove with optional links to discovered properties.
Record acquisition date, purchase price/costs, rent, operating expenses, EMI, outstanding debt
and your own dated valuation. Cash flow = rent - expenses - EMI; equity = valuation - debt;
unrealized gain = valuation - purchase price - purchase costs. Operating yield on cost excludes
financing and taxes. Value/equity totals require every holding to be valued; otherwise they are
unknown. The app never substitutes a portal asking price for a valuation. All records persist
in `portfolio_holdings` with an owner key; existing databases gain the table on startup.
CRUD: GET/POST `/api/portfolio`, PUT/DELETE `/api/portfolio/{id}`.
Check `uv run pytest tests/integration/test_holdings_api.py` for math and date validation.
